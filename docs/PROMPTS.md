# 시험용 프롬프트 모음

기본은 `$fde-pilot` 명령 다섯 개. 아래는 그 사이에 내가 직접 개입할 때 쓰는 문장이다.
원칙: 한 번에 한 가지, 끝나면 멈추게, 증거를 요구, 내 판단은 이유와 함께.

## 0. 세팅 (0~5분)
```
AGENTS.md를 읽고 지금 폴더 구조, 사용할 스킬 목록, 실행 가능한 명령(dart, python3, flutter, serverpod)을 5줄로 보고해. 아무것도 만들지 마.
```
```
$fde-pilot 시작 19:05
```

## 1. 내 판단 전달 ("내가 정할 것"에 답할 때)
```
B로 가. 이유: 담당자가 "바뀌는 팀이 적었으면" 했고, 커버율 2%p보다 반발 줄이는 게 승인에 중요해. DECISIONS.md 사람 결정에 이대로 남겨.
```
- 형식: 결정 + "이유:" + 근거 한 줄(담당자 말 또는 숫자). 이 문장이 인지 축 점수의 재료다.

## 2. AI 제안을 고치거나 거절할 때 (점수 차 나는 장면)
```
그 방식은 쓰지 마. 이유: 담당자가 엑셀만 쓰는데 DB를 붙이면 운영 인계가 안 돼. CSV 입력 그대로 두고, DECISIONS.md "AI 제안 기록"에 네 제안과 거절 이유를 남겨.
```
```
범위 밖이야. 로그인 기능은 만들지 말고 DECISIONS.md "범위 밖"에 이유와 함께 적어.
```

## 3. 검증 요구
```
완료라고 하지 말고 증거를 보여줘. 실행한 명령, 출력, 테스트 결과. 화면 숫자와 /api/evaluate 숫자가 같은지도 직접 비교해.
```
```
제약 위반이 정말 0인지 독립 코드로 다시 세어봐. 솔버 결과를 믿지 말고 결과 파일을 다시 읽어서 채점해.
```
```
네가 만든 테스트가 진짜 잡는지 확인하자. 핵심 검사 한 줄을 일부러 망가뜨려서 테스트가 실패하는지 보여주고 원복해.
```
```
극단 입력 3개로 돌려봐: 빈 파일, 필수 컬럼 누락, 값이 10배. 각각 어떻게 되는지 표로.
```

## 4. 오류가 났을 때
```
고치지 말고 먼저 원인부터. 재현 명령, 에러 위치, 가설 2개와 각각 확인 방법을 보고하고 멈춰.
```
```
2번 가설로 확인해. 맞으면 최소 수정만 하고, 같은 버그를 잡는 테스트를 먼저 추가해.
```

## 5. 데이터와 숫자
```
이 숫자는 코드로 계산해서 근거와 함께 줘. 추정하지 마. 계산 스크립트는 analysis/에 남겨.
```
```
담당자 말과 데이터가 다른 곳이 있는지 찾아. 예: 말한 시각과 실제 기록 평균. 차이를 숫자로 보여주고 질문 초안을 써.
```

## 6. 요구가 바뀌었을 때
```
담당자가 "(바뀐 요구)"라고 했어. 바로 고치지 말고, 이전 합의와 무엇이 다른지, 왜 바뀌었을지 가설 2개, 우리가 먼저 낼 다음 안을 정리해. 회신 초안도.
```

## 7. 화면
```
$web-design 점검표로 지금 화면을 검토해. 고치지 말고 문제 5개를 영향 순으로. 결정권자가 3초 안에 결론을 보는지 먼저 봐.
```
```
1, 2번만 고쳐. 새 기능은 넣지 마. 맨 위 결론 한 줄, 그 아래 기존안 비교, 그 아래 실무 결과 순서 유지.
```

## 8. 스택 선택
```
env_check.sh 결과를 보고 Serverpod로 갈지 Jaspr 템플릿으로 갈지 추천해. 판단 기준: 지금 바로 뜨는가, 10분 안에 화면이 나오는가. 근거 3줄.
```
```
Serverpod로 간다. $serverpod-overview 기준으로 서버 전용, DB 없이 만들고 app/core를 path 의존성으로 연결해. 엔드포인트 하나 만들고 curl로 확인한 결과까지 보여주고 멈춰.
```

## 9. 검토 세션 (130분 전후, 가능하면 /new 새 세션)
```
너는 이 코드를 처음 보는 리뷰어야. 코드를 고치지 말고 docs/work/AGREEMENT.md 기준으로 빠진 것, 틀린 것, 보안, 운영 위험을 표로 보고해. 심각도 순.
```

## 10. 인계와 세션 전환
```
$handoff 해. 다음 세션이 이 파일만 읽고 이어받을 수 있게. 커밋까지.
```

## 11. 시간이 부족할 때
```
$fde-pilot 마무리
```
```
남은 시간 25분. 지금 되는 것만으로 제출 가능한 상태인지 확인하고, 안 되는 기능은 끄고 RESULT.md에 "미완성과 이유"로 남겨.
```

## 12. 서술형 대비 (제출 직전 5분)
```
$cognition-prep 해. 그리고 나한테 서술형 예상 질문 5개를 하나씩 던져. 내가 답하면 빠진 부분만 한 줄로 짚어줘.
```
- 답 구조: 약점 지점 → 파급 → 다음 검증 계획. 내가 정한 판단과 이유를 내 말로.
