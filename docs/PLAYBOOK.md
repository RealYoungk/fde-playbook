# 실전 운영안 (과제 180분 + 후속 서술형)

## 평가 축 (공개된 자료 기준)
| 축 | 보는 것 | 메모 |
|---|---|---|
| 기술 | 실행되는 결과물, 구조, 요구사항 충족, 보안 | |
| 의도 | 목표와 제약 정의, 작업 분해와 위임, 검증 루프 | 변별력이 가장 큼 |
| 인지 | AI 결과의 동작과 위험을 내가 설명 | 참가자 전원이 가장 약했음 |
| 소통 | 다른 사람이나 세션이 이어받을 수 있게 남김 | handoff 문서 |
수집되는 것: 코드, git log와 diff, 테스트 결과, AI 대화와 프롬프트, 도구 설정(AGENTS.md 등), 토큰 사용량.

## 점수 차를 만드는 장면 (기록에 꼭 남기기)
1. AI 제안을 이유와 함께 수정하거나 거절함 → DECISIONS "AI 제안 기록"
2. AI 오류를 내 검증으로 잡아냄 → "불변 조건을 돌려보니 2건 나와. 원인 찾고 멈춰"
3. 판정과 계산은 고정 코드로, AI는 초안으로 경계를 내가 정함
4. AI가 만든 테스트를 의심함 → 검사 한 줄을 지워서 테스트가 실패하는지 확인

## 시작 전 (본 응시 20분 전까지)
- [ ] 노트북, 휴대폰 충전 / 휴대폰 Wi-Fi
- [ ] Proctor 앱 실행, 거치, 구도
- [ ] 실물 신분증, 유선 키보드와 마우스, Chrome 최신
- [ ] 과제 시작 후 녹화가 켜진 다음에 신분증, 얼굴, 안경 확인

## 0~10분: 세팅
```
git clone https://github.com/<계정>/fde-playbook.git /tmp/fde-playbook
bash /tmp/fde-playbook/scripts/install.sh . --app
bash /tmp/fde-playbook/scripts/env_check.sh
git init 2>/dev/null; git add -A; git commit -qm "start"
```
`codex` 실행 → `/status`로 모델, 권한 확인 → 이후는 이 명령만 친다:
```
$fde-pilot 시작 19:05        # 과제 시작 시각. P1(조사, 관계도, 첫 메시지 초안)까지 하고 멈춤
$fde-pilot 답장 <담당자 답 붙여넣기>
$fde-pilot 다음              # 게이트 확인 후 다음 단계
$fde-pilot 상태              # 시간, 단계, 가장 큰 위험
$fde-pilot 마무리            # 기능 작업 중단, 인계와 제출로
```
매 응답에서 내가 할 일은 두 가지: **메시지를 읽고 고쳐서 보내기**, **"내가 정할 것"에 내 말로 이유를 붙여 답하기**.
Codex가 일하는 동안 나는 README를 직접 읽는다. 기다리지 않는다.

## 10~40분: 인터뷰와 서면 합의
- `$fde-discovery`: 관계도(STAKEHOLDERS.md), 도메인 모델(ONTOLOGY.md), 현재 업무 흐름의 막히는 지점
- 1차 질문 5~7개 → 내가 다듬어서 묶어 전송. 선택형은 `$decision-cards` 형식
- 답변 요지를 QUESTIONS.md에 → 목표, 제약, 지표로 변환 (`$objective-and-tradeoffs`)
- AGREEMENT.md 작성 → 담당자 확인 → 커밋 → `$handoff`

## 40~55분: 베이스라인과 구조
- 기존안을 같은 지표로 채점. 이게 있어야 "개선"을 말할 수 있다
- core / web_app 책임 분리를 DECISIONS "구조"에 기록

## 55~100분: 최소 동작 버전
- 단위마다: 구현 → 직접 검증 2가지(VERIFY.md) → 커밋
- **100분 시점에 제출 가능한 상태.** 담당자에게 중간 결과 공유
- `$handoff` 후 필요하면 `/new`

## 100~130분: 시나리오와 개선
- 담당자 피드백 반영, 관점별 시나리오 2~3개
- 검토 세션: "코드 고치지 말고 빠진 것, 틀린 것, 보안과 운영 위험을 표로 보고해"

## 130~150분: 운영 리스크
- 잘못된 입력, 동시 수정, 장애 시 조회, 개인정보, 규칙 변경
- 작게 구현하거나 리스크 표에 기록

## 150~165분: 최종 점검과 문서
- `$baseline-and-verify` 제출 전 체크
- RESULT.md, DECISIONS.md 정리
- `$cognition-prep` → BRIEF.md를 **직접 읽고 고친다**

## 165~180분: 제출
- 종료 10분 전에는 제출을 시작한다 (공식 권고)
- 과제가 지정한 문서명, 경로 확인. 숨김 폴더도 제출물에 포함될 수 있다

## 후속 서술형
- AI, 복사 붙여넣기 금지. 이전 문항으로 못 돌아감
- 답: 지점(파일, 함수, 숫자) → 파급 → 다음 검증/개선. 250~400자

## Codex 사용 요령
- 지시는 목표, 제약, 완료 기준(숫자, 케이스), 검증 방법 4요소로
- 지시 끝에 "끝나면 보고하고 멈춰"
- "완료"가 아니라 실행 출력을 요구
- Esc 중단, Ctrl+J 줄바꿈. 꺼지면 `codex resume` 또는 재실행 후 HANDOFF.md 읽히기
- Codex가 고치는 파일을 에디터에서 동시에 고치지 않기
- Codex 업데이트 금지

## 하지 말 것
- 시작하자마자 범용 스킬을 여러 개 내려받기
- 지시서 전체를 붙여넣고 "해줘"
- "다시 해줘"만 반복 (무엇이 틀렸는지 근거와 함께)
- 요구에 없는 큰 기능 추가
- 베이스라인 없이 "최적" 주장
- 마지막 10분에 큰 변경, 마감 직전 대량 복원 (통째 대체로 오해 소지)
- git push, 외부 AI, 개인 파일 업로드 (금지 사항)

## 장애 대응
- 플랫폼 오류는 시험 화면의 문제 신고 버튼으로 시각과 증상 접수
- 30분마다 커밋, 단계마다 HANDOFF.md
