# 목표 정의와 트레이드오프

## 1. 이해관계자 지도
`STAKEHOLDERS.md`(`$fde-discovery`)의 충돌선을 시나리오 축으로 쓴다. 요약은 `DECISIONS.md`에도 남긴다.

| 이해관계자 | 관심사 | 대표 지표 | 출처 |
|---|---|---|---|
| 예: HR | 이용률, 민원 | 10분 이내 비율, 불리해지는 인원 | 담당자 답변 Q3 |
| 예: 재무 | 비용 | 차량 수, 운행 시간 | 추정 (확인 필요) |
| 예: 이용자 | 편의 | 평균 도보 시간, 탑승 시간 | README R4 |

## 2. 제약과 지표 분리
- **hard 제약**: 위반하면 해가 아님 (규정, 예산 상한, 근무 시간 일치)
- **soft 제약**: 가급적 지킴, 위반 건수를 지표로 보고
- **지표**: 비교에 쓰는 숫자. 방향(높을수록/낮을수록)과 담당 이해관계자를 붙인다.
- 각 제약에 출처(README 조항, 담당자 발언, 가정)를 붙인다. `ops_core`의 `Constraint.source`에 그대로 넣는다.

## 3. 시나리오
- 단일 가중합 점수 하나로 "최적"을 주장하지 않는다. 가중치 자체가 의사결정이기 때문.
- 관점별 시나리오 2~3개 + 사용자 조정 시나리오를 만든다.
- 비교표에서 각 시나리오가 무엇을 얻고 무엇을 잃는지 한 줄로 요약한다.
- 추천안이 있으면 "어떤 조건이면 이 안"이라고 조건부로 말한다.

## 4. 방법 선택 기준
- 설명 가능성 > 최적성. 서술형에서 "왜 이 방법인가"를 설명할 수 있어야 한다.
- 우선순위: 규칙 기반 → 탐욕 (예: `greedyMaxCoverage`) → 지역 탐색 개선 → 수리 최적화.
- 결과가 직관에 맞는지 작은 예제로 손계산 대조한다.

## 5. 기록
- 선택한 방법, 버린 대안, 버린 이유를 `DECISIONS.md`에 남긴다.
