# 의사결정 로그

## 결정 항목 형식 (`docs/work/DECISIONS.md`)
```
### D7. 도보 허용 한계를 10분으로 설정
- 맥락: 담당자 "15분 넘으면 안 탈 수도" (Q3)
- 선택: 커버 기준 10분, 15분 초과는 soft 제약
- 대안: 15분 기준 (거점 수 줄지만 이용률 하락 우려)
- 근거: 비교표에서 10분 기준이 차량 +2대로 커버율 +18%p
- 되돌리는 조건: 재무팀이 차량 상한을 두면 비용 우선 시나리오로 전환
```
가정은 `### A3. (가정)`으로 쓰고, 담당자 확인 후 확정/폐기를 표시한다.

## AI 제안 기록
AI 제안을 그대로 받지 않고 바꾸거나 거절했을 때 한 줄씩:
`- [거절] 캐시 레이어 추가 제안: 데이터 갱신이 하루 1회라 불필요 (Q5)`
`- [수정] 유전 알고리즘 제안 → 탐욕 + 지역 개선: 설명 가능성과 시간`

## 운영 리스크 표
| 상황 | 영향 | 대비 (구현/문서) | 상태 |
|---|---|---|---|
| 잘못된 입력 파일 | 결과 오염 | 행 검증, 실패 행 보고, 기존 확정본 유지 | |
| 동시 수정 | 덮어쓰기 | 버전 확인 후 충돌 시 409 | |
| 서버 장애 중 조회 | 시간표 못 봄 | 확정본을 정적 파일로 저장, 기준 시각 표시 | |
| 개인정보 | 주소 노출 | 화면과 API에서 개인 단위 좌표 제거 | |
| 규칙 변경 | 기존안과 차이 | 초안으로 재계산 후 전후 비교, 확정은 별도 | |
요청되지 않은 대비를 크게 만들지 않는다. 작게 구현하거나 표에만 남긴다.

## RESULT.md 구성
1. 한 줄 결론 (조건부 추천)
2. 실행 방법
3. 비교표 (`/api/report.md`)
4. 시나리오별 얻는 것과 잃는 것
5. 주요 가정과 확인 상태, 틀리면 영향
6. 검증 방법과 결과
7. 한계와 다음 단계
8. 운영 인계: 메인테이너, 기준을 바꾸는 법(파라미터와 설정 위치), 데이터 교체 방법, 재계산과 검증 명령
