# 업무용 웹 디자인

이 화면의 목적은 결정권자가 **3초 안에 결론을 보고, 30초 안에 근거를 확인**하는 것이다. 예쁜 랜딩 페이지가 아니라 신뢰할 수 있는 운영 도구처럼 보여야 한다. 평가 쪽에서도 프런트 화면 캡처와 실행 상태를 점검한다.

## 1. 정보 구조 (위에서 아래로)
1. **결론**: 화면 제목 아래 한 줄. "균형안: 기존 대비 10분 내 이용 +70%p, 차량 +2대" 같은 조건부 추천
2. **선택한 안의 KPI 카드**: 지표 4~6개. 값 크게, 기존안 대비 변화 작게, 개선은 초록 악화는 주황
3. **근거 시각화**: 지도, 시간표, 분포 등 도메인 화면 1개 + 파라미터 조절
4. **비교표**: 열 = 기존안과 각 시나리오, 행 = 지표. 선택한 열 강조
5. **제약과 가정, 출처**: 담당자 발언 번호, 미확정 결정
6. 데이터 출처, 계산 엔진, 기준 시각 (작게)

## 2. 디자인 토큰 (template의 `web/styles.css`)
- 색은 토큰으로만 쓴다. 배경은 약간 따뜻한 중립, 강조색 1개, 상태색 2개(개선/악화). 순수 검정과 회색 대신 색조가 살짝 들어간 중립색(OKLCH)
- 간격은 4px 배수 스케일(4, 8, 12, 16, 24, 32)만 쓴다
- 글꼴은 시스템 한글 폰트 스택. **외부 CDN 폰트 금지**(시험 환경 네트워크 불확실, 평가 감점 위험)
- 숫자 열과 KPI에 `font-variant-numeric: tabular-nums`. 표의 숫자는 오른쪽 정렬
- 모서리 반경, 그림자는 하나씩만. 카드 안에 카드 넣지 않기
- 한글은 `word-break: keep-all`, 제목은 `text-wrap: balance`

## 3. 컴포넌트 패턴
| 필요 | 패턴 |
|---|---|
| 안 비교 | 비교표 + 선택 열 강조 + 변화량 보조 줄 |
| 핵심 수치 | KPI 카드 (라벨, 값, 기존 대비) |
| 위치 데이터 | SVG 산점 지도 (타일 없이 위경도 투영), 커버 반경 원, 범례 |
| 시간표 | 행 = 지점(순서), 열 = 회차, 셀 = 시각. 최종 도착 열 굵게 |
| 파라미터 | 숫자 입력 + 단위 + 한 줄 도움말(출처). GET 폼이면 상태가 URL에 남아 공유 가능 |
| 엔진/보기 전환 | 세그먼트 컨트롤, 탭 (링크로 구현) |
| 결정 대기 | 노란 배지 "담당자 확인 대기" + 현재 기본값 |
| 위반 | 필수/권고 태그 + 건수 + 상세 목록 |

## 4. 상태 처리 (빠지기 쉬움)
- 빈 데이터: "표시할 데이터가 없습니다" + 다음 행동
- 오류: 무엇이 실패했고 무엇으로 대체했는지 (`role="alert"`)
- 해 없음(infeasible): 0으로 표시하지 말고 "제약 안에서 해 없음, 목표나 예산 조정 필요"
- 긴 이름, 많은 행: 표는 가로 스크롤 컨테이너, 셀은 줄바꿈 정책 명시

## 5. 접근성과 기본기
- 모든 입력에 `<label>`, 표에 `<th scope>`, 지도 SVG에 `role="img"`와 `aria-label`
- `:focus-visible` 아웃라인 유지, hover와 focus 상태가 기본 상태보다 눈에 띄게
- 동작은 `<button>`, 이동은 `<a>`. 클릭 가능한 div 금지
- 색만으로 의미를 전달하지 않기 (변화량 앞에 +/- 기호, 태그 글자)
- 모바일 폭(390px)에서 깨지지 않는지 한 번 확인

## 6. 피해야 할 것 (AI가 만든 티가 나는 화면)
- 보라-파랑 그라데이션 배경, 네온 글로우, 과한 그림자
- 모든 제목 위에 둥근 아이콘, 이모지 장식
- 큰 숫자 하나만 덩그러니 있는 히어로 섹션
- 회색 배경 위 회색 글씨 (대비 부족)
- 의미 없는 애니메이션, `transition: all`
- 카드 안의 카드 안의 카드
- "Lorem", "Sample", 영어 더미 문구가 남아 있는 화면

## 7. 점검 절차 (구현 후, 제출 전)
1. 내장 Browser로 화면을 열고 위 1번 구조대로 위에서 아래로 읽어본다. 결론이 3초 안에 보이나
2. `references/checklist.md` 항목을 체크
3. 파라미터를 극단값으로 바꿔 상태 처리 확인
4. 고친 점을 `VERIFY.md`에 "화면 조작, 실행자: 사람"으로 기록

## 함께 쓰는 외부 스킬과 자료
- `references/vercel-web-interface-guidelines.md`: Vercel Web Interface Guidelines 원문(MIT). 제출 전 점검 시 "이 규칙으로 화면 파일을 리뷰해"라고 지시
- `$frontend-design` (Anthropic, 기본 설치): 미적 방향을 정할 때. 단, 이 과제는 업무 도구라 대담함보다 정확함과 절제가 우선
- `$impeccable` (설치 옵션 `--impeccable`): 디자인을 크게 다듬을 때. 첫 실행 시 엔진을 내려받으므로 네트워크가 필요하고 토큰을 많이 쓴다. 시간이 남을 때만
- `$jaspr-fundamentals`, `$jaspr-styling` (기본 설치): Jaspr 문법, 스타일링

## Jaspr 메모
- `lib/app.dart`에서 HTML 요소 함수(`div`, `table`, `svg`, `circle`)로 구성, 스타일은 `web/styles.css` 클래스로
- SVG `fill`은 Color 타입이라 클래스와 CSS로 칠하는 편이 간단하다
- 상태는 쿼리스트링에 두고 GET 폼과 링크로 바꾼다 (클라이언트 JS 빌드 불필요)
