# 방법론 출처 요약

## 팔란티어 FDE
- 고객 현장에 들어가 문제를 발굴하고 솔루션을 직접 만드는 역할. 디스커버리 대화를 엔지니어링 업무로 본다.
- 도메인을 엔티티, 속성, 링크로 먼저 모델링(온톨로지)하고, 분석가가 한 번에 끝까지 쓰는 의사결정 흐름 하나를 빨리 배포한 뒤 피드백으로 반복한다. "요구사항 문서보다 작동하는 코드".
- 채용 시 decomposition 라운드: 모호한 실제 문제를 구조화하는 능력, 최종 사용자 공감, 데이터 추론, 범위 자르기, 반론에 따른 수정. 강한 지원자는 처음 10분을 질문에 쓰고(누가 쓰나, 늦으면 무엇이 깨지나, 사용자 수와 숙련도), 가장 작은 가치 단위 해법을 제안하며, 범위 결정을 근거로 방어한다. 흔한 실수는 듣자마자 아키텍처부터 말하기, "완료" 정의 전에 설계, 과도하게 완전한 시스템.

## 스페이스와이 (한국형 FDE, 황현태 대표, 유튜브 '까칠한AI')
- 본편 19개 영상의 상세 노트는 `kkachilhan-notes.md`. 핵심: 토폴로지 스캔(사람부터), 난제에 집중, 암묵지와 컨텍스트 그래프, 종으로 연결된 AX, 버려져야 한다(내재화와 메인테이너), 업무별 에이전트 남발 경계, 워크슬롭.
- FDE = 컨설턴트 + 엔지니어. 분석과 권고에서 멈추지 않고 코드로 실제 동작까지 책임.
- 2인 팀으로 상주. 조직 구조를 파악하고 상위 의사결정자와 소통하는 역할을 따로 둔다 (위계 문화에서 낮은 연차가 임원을 직접 설득하기 어렵기 때문).
- "오늘 어떤 얘기가 나오든, 모레까지는 눈으로 볼 수 있게 만든다." 가완성 시스템을 보여주고 빨간 펜을 그어 가며 니즈를 구체화한다. 고객은 원하는 것을 정확히 모르는 경우가 많다.
- 진행: 타사 사례 스터디로 자동화 타깃 3~5개 → 현장 밀착으로 주 단위 요구 수집, 프로토타입 기준으로 예외와 승인 룰 결정 → 우선순위 1~2개 흐름을 90%까지 동작시키는 데모, Before/After 캡처와 체크리스트로 만족도 수치화 → KPI 기반 계약 → 위험 낮은 팀부터 점진 배포.
- 첫 1~2주 안에 고객이 원하는 것을 빠르게 실행해 신뢰를 얻은 뒤 본격적인 개선으로 들어간다.
- 전사 거대 담론이 아니라 부서 단위 성공 사례부터 만든다.

## 이 과제에의 적용
| 현장 방식 | 180분 과제 버전 |
|---|---|
| 조직 구조, 의사결정자 파악 | 0~15분 관계도 (STAKEHOLDERS.md) |
| 온톨로지 우선 | 데이터 컬럼을 엔티티/관계로 매핑 (ONTOLOGY.md) |
| 모레까지 눈으로 | 합의 후 30분 안에 v0 화면 공유 |
| 빨간 펜 | 화면에 결정 포인트를 드러내고 담당자가 고르게 (decision-cards) |
| 90% 데모, Before/After | 기존안 대비 비교표, KPI 카드 |
| KPI 기반 | 서면 합의의 숫자 성공 기준 |
| 점진 배포 | 운영 리스크 표, 초안 후 확정 흐름 |
