# 데이터 점검, 베이스라인, 검증

## 데이터 점검 (조사 단계)
```dart
import 'package:ops_core/ops_core.dart';
final rows = readCsvFile('data/xxx.csv');
print(profileRows('xxx', rows).toMarkdown());
final v = validateRows(rows, [
  RowRule.required('employee_id'),
  RowRule.number('lat', min: 33, max: 39),
  RowRule.oneOf('shift', {'주간', '야간', '교대'}),
], keyColumn: 'employee_id');
print(v.toMarkdown());
```
- 결과를 `DECISIONS.md` "데이터 점검"에 붙이고 처리 방침(제외, 보정, 질문)을 정한다.
- 잘못된 행은 조용히 빼지 않고 몇 건, 왜 뺐는지 보고한다.

## 베이스라인
- 기존 운영안이 있으면 `scoreSolution(Scenario(id: 'baseline', label: '기존안'), ...)`으로 같은 지표를 계산한다.
- 없으면 단순 규칙 해를 베이스라인으로 둔다.

## 직접 검증 (AI 테스트만 믿지 않기)
AI가 만든 함수를 AI가 만든 테스트로만 확인하면 같은 착각을 반복한다. 단계마다 아래 중 최소 두 가지를 하고 `VERIFY.md`에 "실행자: 사람/AI"를 구분해 남긴다.

| 방법 | 내용 |
|---|---|
| 작은 케이스 | 손으로 답을 아는 최소 데이터(3~5건)로 결과 대조 |
| 불변 조건 | 항상 성립해야 할 규칙을 별도 코드로 셈 (예: 전원 배정, 정원 초과 0건, 시간 역전 0건) |
| 다른 경로 재계산 | 화면 숫자를 원본 파일에서 독립 스크립트로 다시 계산 |
| 일부러 깨뜨리기 | 빈 입력, 잘못된 형식, 극단 파라미터, 중복 키 |
| 테스트를 테스트 | 핵심 검사 한 줄을 지우거나 뒤집어 테스트가 실패하는지 확인 |
| 단조성 | 파라미터를 키우면 지표가 예상 방향으로 움직이는지 |
| 화면 조작 | 사용자처럼 입력부터 결과까지 직접 눌러 봄 |

불일치가 나오면 "다시 해줘"가 아니라 근거를 들어 지시한다: "불변 조건을 돌려보니 정원 초과가 2건 나와. 원인 찾아서 보고하고 멈춰."
실패와 수정 기록은 지우지 않는다. `DECISIONS.md` "오류와 수정"에도 남긴다.
