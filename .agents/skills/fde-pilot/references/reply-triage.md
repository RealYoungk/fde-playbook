# 담당자 답장 처리 순서

1. **원문 보관**: `QUESTIONS.md`의 해당 Q에 원문 그대로 붙인다. 받은 시각을 같이.
2. **문장별 분류**: 각 문장을 하나로 태깅한다.
   | 태그 | 신호 | 반영 위치 |
   |---|---|---|
   | 목표 | "줄이고 싶다", "~가 중요" | AGREEMENT 목표, 지표 |
   | 제약 | "안 된다", "반드시", 시간, 수량 | AGREEMENT 제약, 코드의 제약 키 |
   | 사람 | 다른 사람, 부서, 상사 언급 | STAKEHOLDERS 표에 추가 또는 갱신 |
   | 암묵지 | "보통", "원래", "관행상", "예외로", "실제로는" | QUESTIONS 해석에 "화자, 맥락" 붙여 기록, 규칙 후보 |
   | 결정권 | "윗선", "본부장님이", "재무에서" | STAKEHOLDERS 숨은 결정권, 결과 화면에 그 사람이 볼 숫자 |
   | 변경 | 이전 말과 다름 | DECISIONS에 이전/이후, 이유 질문 |
   | 모름 | "잘 모르겠다", "알아서" | decision-cards 기본값으로 진행, 화면에서 조절 가능하게 |
3. **충돌 확인**: 이전 답이나 데이터와 다르면 3단계로 본다. 사실 오류인가 → 상황이 다른가(누가, 언제, 어느 팀 기준) → 그래도 다르면 "원래 어떻게 하셨어요?"
4. **데이터와 대조**: 답이 데이터로 확인 가능하면 코드로 확인한다. 말과 데이터가 다르면 숫자를 붙여 정중하게 묻는다. 예: "기록상 실제 도착은 평균 12:10인데, 기준을 12:00로 둘까요 12:10로 둘까요?"
5. **숨은 사정 감지**: 아래가 보이면 "내가 정할 것"으로 올린다.
   - 처음 말한 이유와 다른 진짜 계기(민원, 사고, 윗선 지시)
   - 바뀌는 사람 수나 팀 수를 신경 쓰는 표현 → 변경 최소화 지표 추가 후보
   - 특정 집단만 예외 허용 → 규칙 분기
   - 엑셀만 쓰는 운영자 → 인계를 CSV 입력과 버튼 하나로
6. **회신 초안**: 받은 내용 확인 한 줄 + 아직 비어 있는 질문 최대 2개 + 다음에 보여줄 것. `references/messages.md` 틀을 따른다.
