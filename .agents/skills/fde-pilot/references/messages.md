# 담당자 메시지 틀

공통: 6줄 이하, 첫 줄에 용건, 질문에는 번호와 기본값, 해결책 단어는 P1에서 금지, em dash 금지.
담당자가 답하기 쉬운 순서: 고르기 > 숫자 하나 > 짧은 서술.

## P1 첫 메시지
```
안녕하세요, 이번 건 맡은 김영진입니다. 자료 보고 이렇게 이해했습니다.
- (문제 한 줄) / (지금 방식 한 줄)
몇 가지만 여쭙겠습니다. 답이 어려우면 괄호 안 기본값으로 진행하겠습니다.
1. (간극) 개편으로 손해 보는 사람이 생기면 누구 편의를 우선할까요? (기본: 이용 인원이 많은 쪽)
2. (대리) 이 안은 최종적으로 누가 승인하시나요? 그분이 꼭 보는 숫자가 있을까요?
3. (암묵지) 규칙에는 없지만 실제로 예외로 처리하는 경우가 있나요?
4. (메인테이너) 개편 후 기준이 바뀌면 누가 다시 돌리게 될까요?
```

## P2 합의 요청
```
말씀 주신 걸로 이렇게 진행하려 합니다. 다르면 한 줄만 고쳐 주세요.
- 목표: (숫자 성공 기준)
- 만들 것: (화면 1개, 기능 2~3개) / 이번엔 안 할 것: (항목)
- 지켜야 할 것: (제약 2~3개)
- 정해지지 않은 (항목)은 (기본값)으로 두고 화면에서 바꿀 수 있게 하겠습니다.
```

## P3 빨간 펜 요청
```
첫 버전 화면 공유드립니다. (주소)
- 결론: (한 줄)
- 기존안 대비: (지표 A) X→Y, (지표 B) X→Y
두 가지만 봐 주세요.
1. (가장 자신 없는 가정)이 현장과 맞나요?
2. 현업이 보시기에 이상한 결과가 있나요? 한 줄이면 충분합니다.
```

## P4 요구가 바뀌었을 때
```
네, (바뀐 요구) 반영하겠습니다. 혹시 (이유를 묻는 한 줄)인가요?
그렇다면 (우리가 먼저 내는 다음 안)도 같이 비교해서 보여드리겠습니다. (예상 영향 한 줄)
```

## P4 시나리오 선택 요청
```
관점별로 세 가지 안을 비교했습니다. (주소)
A (이용자 우선): ... / B (비용 우선): ... / C (균형): ...
추천은 (안)입니다. (이유 한 줄)
(결정권자)께 보고하실 때는 (어떤 숫자)를 보시면 됩니다.
```

## P6 최종 보고
```
결론: (한 줄)
- 기존안 대비 (숫자 2개)
- 남은 위험: (하나)와 대응
- 운영: 기준은 (위치)에서 바꾸고 (명령)으로 다시 계산합니다. 자세한 건 RESULT.md "운영 인계".
- 다음에 하면 좋은 것: (하나)
```

## 피할 표현
